# Send flow

When Senda sends an email, it follows a resolution chain instead of guessing.

## The short version

1. Parse the request reference
2. Resolve the scope chain
3. Resolve the template
4. Merge injectors
5. Resolve the adapter
6. Send the message
7. Record tracking and events

## How resolution works

Senda resolves from the most specific scope to the least specific one:

- workspace
- `_system`
- global

That lets a workspace override defaults from the tenant or platform without copying everything.

## Templates, injectors, and adapters

These three parts do different jobs:

- **Templates** define the content
- **Injectors** provide data to the template
- **Adapters** deliver the email through the provider

The adapter is chosen by template type, not by copying the same configuration everywhere.

## API keys and the data plane

The data-plane APIs use workspace API keys.

That is why the API key guide and the workspace API Docs page matter together:

- [API Keys](api-keys)
- workspace API Docs page in the sidebar

## Bulk send from the template UI

The template editor also exposes a **Bulk Send** action in workspace scope.

- it uses the current **published** template version
- the uploaded JSON contains only `items[]`
- the UI validates and previews the payload before enqueuing
- the backend reuses the same batch send engine as the API-key batch endpoint

Use **Send Test** for a single verification email.
Use **Bulk Send** when you want to enqueue many real messages from the same template.

## When a send fails

Failures usually mean one of these:

- no adapter is configured in the chain
- the template cannot be resolved
- required injector data is missing
- the provider rejects the send
