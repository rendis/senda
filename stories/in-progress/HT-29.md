# HT-29: Auth (OIDC) + Scope Switcher + Protected Routes

## Objetivo
Implementar autenticación OIDC con Auth.js (next-auth v5), scope switcher (Global/Tenant/Workspace), pantallas de Login y Access Denied, y protección de rutas según rol.

## Entregables

1. **Auth.js (next-auth v5)**
   - Configurar provider OIDC genérico
   - Session management con JWT
   - Middleware de protección de rutas (`middleware.ts`)
   - API client (ky) con token injection automático

2. **Pantalla Login**
   - Leer via Pencil MCP el frame "Screen/Login" (Layer 5)
   - Implementar: card centrada, logo Senda, botón OIDC, footer
   - Redirect a OIDC provider → callback → dashboard

3. **Pantalla Access Denied**
   - Leer via Pencil MCP el frame "Screen/Access Denied" (Layer 6)
   - Implementar: card centrada, icono, mensaje con email del usuario, botón cerrar sesión

4. **Scope Switcher**
   - Componente dropdown que muestra: nivel actual (Global/Tenant/Workspace), tenants disponibles, workspaces del tenant seleccionado
   - Al cambiar scope → actualizar contexto global (React Context o Zustand)
   - URL refleja el scope: `/t/{tenantCode}/w/{workspaceCode}/...`

5. **Protected Routes**
   - Middleware que verifica: autenticado → tiene membresía → tiene rol para la ruta
   - Redirecciones: no auth → /login, no member → /access-denied, sin permiso → 403 page
   - Role-based UI: ocultar elementos según rol (no deshabilitar)

## Reutilización

**Componentes que reutiliza de HT-28:**
- `ScopeIndicator` — mostrado en header y scope switcher dropdown

**Componentes nuevos a extraer:**
- `AuthGuard` — HOC/wrapper para proteger rutas según autenticación y rol
- `ScopeSwitcher` — dropdown component para cambiar contexto Global/Tenant/Workspace
- `LoginForm` — form de OIDC reutilizable

## Metodología

Feature-first: esta HT entrega una feature vertical completa (autenticación + scope management + protected UI). Verifica que `ScopeIndicator` de HT-28 se reutiliza en el header y scope switcher antes de crear nuevos componentes. Los componentes `AuthGuard`, `ScopeSwitcher`, y `LoginForm` son extracciones que refuerzan la composición y pueden ser usados en HT-30 y HT-31.

## Criterios de Aceptación

- [ ] Login flow OIDC funciona end-to-end
- [ ] Access Denied se muestra para usuarios sin membresía
- [ ] Scope switcher cambia contexto y URL
- [ ] Rutas protegidas redireccionan correctamente
- [ ] Diseño matchea frames de Pencil (verificado via MCP)
- [ ] Session persiste en refresh

## Definition of Done (DoD)

Cada feature se considera terminada SOLO cuando cumple estos 3 gates:

### Gate 1: Validación Visual (Pixel-Perfect)
1. Levantar la app en dev (`npm run dev`)
2. Navegar a la pantalla implementada
3. Tomar screenshot via herramienta (o manualmente)
4. Leer el frame correspondiente del diseño via Pencil MCP
5. Comparar screenshot vs diseño de Pencil lado a lado
6. Verificar:
   - [ ] Layout y espaciado coinciden
   - [ ] Colores y tipografía correctos
   - [ ] Componentes del Design System usados (no custom)
   - [ ] Responsive: verificar en 1440px, 1024px, 768px
   - [ ] Empty states coinciden con diseño
   - [ ] Dark/light mode si aplica
7. Si hay drift visual → corregir en código, NO en Pencil

### Gate 2: Integración con Backend
1. Conectar contra backend real (docker-compose up)
2. Verificar cada endpoint que la feature consume:
   - [ ] GET lista carga datos reales
   - [ ] POST/PUT crea/edita correctamente
   - [ ] DELETE (soft) funciona con confirmación
   - [ ] Errores del backend se muestran correctamente (toast + mensaje)
   - [ ] Loading states mientras espera respuesta
   - [ ] Paginación cursor-based funciona
   - [ ] Filtros y búsqueda funcionan
3. Verificar auth:
   - [ ] Sin token → redirect a login
   - [ ] Token expirado → refresh o redirect
   - [ ] Rol insuficiente → mensaje de error, no crash

### Gate 3: Funcionalidad Completa
1. Todos los criterios de aceptación de la HT cumplidos
2. Componentes reutilizados del Design System (no duplicados)
3. Nuevos componentes extraídos a `components/shared/` si aplican
4. Zero errores en console del browser
5. Zero warnings de TypeScript
6. `npm run lint` pasa
7. `npm run build` compila sin errores
