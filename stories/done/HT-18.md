# HT-18: Auth Middleware (OIDC + API Keys)

**Épica:** E5 — API Layer
**Spec:** §14.2 (Auth Middleware), §14.3 (RBAC Middleware)

## Objetivo

Implementar autenticación dual: OIDC JWT para management plane, API Keys para data plane.

## Entregables

- `internal/http/middleware/auth.go` — `AuthMiddleware`
  - Detecta tipo de auth: `Bearer` → OIDC, `ApiKey` → API Key
  - OIDC: verifica JWT contra discovery URL, extrae email → busca member
  - API Key: hash → lookup → verify active
- `internal/http/middleware/rbac.go` — `RequireRole(minRole)`
  - Role hierarchy: superadmin > tenant_admin > workspace_admin > workspace_editor > workspace_viewer

## Criterios de Aceptación

- [x] OIDC token válido → authenticated
- [x] OIDC token inválido → 401
- [x] API Key válida → authenticated
- [x] API Key revocada → 401
- [x] Missing auth header → 401
- [x] RBAC: viewer no puede hacer POST → 403
- [x] RBAC: superadmin puede acceder a cualquier scope
- [x] Tests unitarios con OIDC mock y API key fixtures

## Notas de Implementación

- Auth detection: `Bearer <token>` con prefix `senda_live_` → API key path, else OIDC path.
- API key: SHA-256 hash lookup via `APIKeyStore.GetByHash`. TouchLastUsed fire-and-forget goroutine.
- OIDC: `OIDCVerifier` port interface en `internal/port/auth.go`. Adapter real se implementa en HT futuro.
- No se agrego `go-oidc` como dependencia — el port solo usa tipos stdlib.
- RBAC: `RequireRole(minRole, tenantStore, wsStore)` — resuelve codes → IDs inline.
- API key auth bypasses RBAC (data-plane only).
- Superadmin bypasses all scope checks. TenantAdmin cubre workspaces dentro de su tenant.
- 19 unit tests (10 auth + 9 RBAC), todos pasan con `-race`.
