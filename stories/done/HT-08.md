# HT-08: PostgreSQL Stores — Injectors, Adapters, Domains, Templates

**Épica:** E2 — Core Domain
**Spec:** §10.2, §3.4–3.8

## Objetivo

Implementar stores para las entidades de configuración de envío.

## Entregables

- `internal/adapter/postgres/injector_repo.go` — InjectorStore (definitions + fields + values, con resolución por chain)
- `internal/adapter/postgres/adapter_repo.go` — AdapterStore (con encrypt/decrypt de credentials)
- `internal/adapter/postgres/domain_repo.go` — DomainStore (con búsqueda por chain, pending verification)
- `internal/adapter/postgres/template_repo.go` — TemplateTypeStore + TemplateStore + TemplateVersionStore + TemplateVersionLocaleStore
- Resolución por chain: queries usan `workspace_id IN (unnest(get_resolution_chain($1)))` o equivalent Go logic
- Version management: publish (con validación one-published), archive, draft

## Criterios de Aceptación

- [x] Injector values se crean/resuelven por scope (workspace → _system → global)
- [x] Adapter credentials se encriptan al guardar y decriptan al leer
- [x] Template versions respetan el constraint one-published
- [x] Domain lookup busca en la cadena de resolución
- [x] Tests de integración: crear datos en distintos scopes y verificar resolución

## Notas de Implementación

- Domain model refactored: InjectorField (removed IsRequired/DefaultValue, renamed DefinitionID→InjectorDefinitionID, SortOrder→Position), InjectorValue (replaced FieldID with InjectorDefinitionID+FieldName), Template (removed Slug/Name not in DB), TemplateVersionLocale (VersionID→TemplateVersionID)
- `splitChain()` helper handles NULL workspace_id in chain queries (shared across repos)
- Chain resolution ordering: workspace-scoped preferred over global via CASE WHEN
- Injector value JSONB ↔ string conversion via json.Marshal/Unmarshal with custom scanInjectorValue
- Adapter encryption at service layer — repo stores bytes as-is
- Template publish uses transaction: archive previous + update target
- CreateVersion auto-calculates version_number in transaction
- 53 integration tests total (12 injector, 11 adapter, 11 domain, 19 template)
