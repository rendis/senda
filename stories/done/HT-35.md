# HT-35: CRUD Views — Webhooks + API Keys + Members

## Objetivo
Implementar las vistas CRUD para Webhooks, API Keys y Members con gestión de roles y scopes.

## Entregables

1. **Webhooks**
   - Leer via Pencil MCP el frame "Screen/Webhooks" (Layer 16)
   - Lista: URL (truncada), eventos suscritos (badges), status (active/disabled), failures count
   - Warning badge si consecutive_failures > 0
   - Crear/Editar: URL (HTTPS obligatorio), eventos (multiselect checkboxes), secret (mostrado 1 sola vez)
   - [Test Webhook]: envía ping → muestra status code + latencia
   - Fetch: `GET /api/v1/manage/t/{tc}/w/{wc}/webhooks`

2. **API Keys**
   - Leer via Pencil MCP el frame "Screen/API Keys" (Layer 17)
   - Lista: nombre, hint (últimos 8 chars), creado por, fecha, último uso, status
   - Generar nueva: input nombre + [Generar] → modal con key completo + [Copiar] + aviso "no se mostrará otra vez"
   - Revocar: confirmación modal destructiva
   - Fetch: `GET /api/v1/manage/t/{tc}/w/{wc}/api-keys`

3. **Members**
   - Leer via Pencil MCP el frame "Screen/Members" (Layer 18)
   - Lista: email, nombre, roles por scope (badges), fecha ingreso
   - Invitar: email + rol + scope (dropdown tenant/workspace)
   - Editar roles: cambiar rol por scope
   - Revocar acceso: confirmación modal
   - Role-based: solo admins ven botón invitar, solo superadmin puede asignar tenant-admin
   - Fetch: `GET /api/v1/manage/t/{tc}/members` o `/w/{wc}/members`

## Reutilización

**Componentes que reutiliza de HT-28:**
- `PageShell` — layout principal
- `DataTable` — tablas de webhooks, API keys, members
- `FormDialog` — forms para crear webhook, generar API key, invitar miembro
- `EmptyState` — cuando no hay recursos
- `ConfirmDialog` — para revocar access, confirmar delete webhook, revocar API key

**Componentes nuevos a extraer:**
- `SecretRevealField` — campo que muestra secret 1 sola vez con [Copiar] (reutilizable para API keys y webhook secrets)
- `WebhookEventPicker` — multiselect de eventos para webhooks
- `RoleBadge` — badge semántico por rol (viewer, editor, admin, superadmin)

## Metodología

Feature-first: Webhooks + API Keys + Members es un conjunto de 3 features que comparten structure de CRUD. Reutiliza `PageShell`, `DataTable`, `FormDialog`, `EmptyState`, `ConfirmDialog` de HT-28. Extrae `SecretRevealField` (crucial para UX de secrets), `WebhookEventPicker`, y `RoleBadge` como componentes especializados. El `SecretRevealField` es especialmente importante: usado en API Keys y webhook secrets, refuerza la composición.

## Criterios de Aceptación

- [ ] Webhooks CRUD completo con test ping
- [ ] API Key generación muestra key 1 sola vez
- [ ] API Key revoke con confirmación
- [ ] Members invitación con rol + scope
- [ ] Role-based visibility funciona
- [ ] Diseño matchea frames de Pencil (via MCP)

## Definition of Done (DoD)

Cada feature se considera terminada SOLO cuando cumple estos 3 gates:

### Gate 1: Validación Visual (Pixel-Perfect)
1. Levantar la app en dev (`npm run dev`)
2. Navegar a la pantalla implementada
3. Tomar screenshot via herramienta (o manualmente)
4. Leer el frame correspondiente del diseño via Pencil MCP
5. Comparar screenshot vs diseño de Pencil lado a lado
6. Verificar:
   - [ ] Layout y espaciado coinciden
   - [ ] Colores y tipografía correctos
   - [ ] Componentes del Design System usados (no custom)
   - [ ] Responsive: verificar en 1440px, 1024px, 768px
   - [ ] Empty states coinciden con diseño
   - [ ] Dark/light mode si aplica
7. Si hay drift visual → corregir en código, NO en Pencil

### Gate 2: Integración con Backend
1. Conectar contra backend real (docker-compose up)
2. Verificar cada endpoint que la feature consume:
   - [ ] GET lista carga datos reales
   - [ ] POST/PUT crea/edita correctamente
   - [ ] DELETE (soft) funciona con confirmación
   - [ ] Errores del backend se muestran correctamente (toast + mensaje)
   - [ ] Loading states mientras espera respuesta
   - [ ] Paginación cursor-based funciona
   - [ ] Filtros y búsqueda funcionan
3. Verificar auth:
   - [ ] Sin token → redirect a login
   - [ ] Token expirado → refresh o redirect
   - [ ] Rol insuficiente → mensaje de error, no crash

### Gate 3: Funcionalidad Completa
1. Todos los criterios de aceptación de la HT cumplidos
2. Componentes reutilizados del Design System (no duplicados)
3. Nuevos componentes extraídos a `components/shared/` si aplican
4. Zero errores en console del browser
5. Zero warnings de TypeScript
6. `npm run lint` pasa
7. `npm run build` compila sin errores
