# HT-36: Audit Log + Settings + Empty States

## Objetivo
Implementar Audit Log con filtros y JSON diff, Settings para superadmin, y empty states para todas las pantallas.

## Entregables

1. **Audit Log**
   - Leer via Pencil MCP el frame "Screen/Audit Log" (Layer 19)
   - Tabla paginada: fecha, quién (email), acción (badge), recurso, scope
   - Filtros: fecha (rango), acción (multiselect), recurso type, miembro
   - Click en fila → detalle con JSON diff (antes/después)
   - Paginación cursor-based
   - Fetch: `GET /api/v1/manage/audit-log`

2. **Settings (solo scope global, superadmin)**
   - Leer via Pencil MCP el frame "Screen/Settings" (Layer 20)
   - OIDC: Discovery URL, Client ID, client secret oculto
   - Email defaults: max retries, backoff base, log retention days
   - Alertas: bounce threshold %, complaint threshold %
   - Dominio: recheck interval hours
   - Solo visible si rol = superadmin y scope = global
   - Fetch: `GET /api/v1/manage/settings`, `PUT /api/v1/manage/settings`

3. **Empty States (todas las pantallas)**
   - Implementar empty states para cada vista según DESIGN_BRIEF §8:
     - Emails: "No hay emails en este período..."
     - Templates: "No hay tipos de plantilla configurados..."
     - Injectors: "No hay inyectores definidos..."
     - Adapters: "No hay adapters configurados..."
     - Domains: "No hay dominios registrados..."
     - Webhooks: "No hay webhooks configurados..."
     - API Keys: "No hay API Keys activas..."
     - Members: "No hay miembros en este scope..."
     - Audit Log: "No hay eventos registrados..."
   - Cada empty state tiene un CTA (botón para crear el primer recurso)

4. **Loading States / Skeletons**
   - Skeleton loaders para tablas, cards, y forms
   - Suspense boundaries en App Router

## Reutilización

**Componentes que reutiliza de HT-28:**
- `PageShell` — layout principal
- `DataTable` — tabla de audit log
- `EmptyState` — cuando no hay eventos o no hay settings

**Componentes nuevos a extraer:**
- `AuditLogEntry` — componente individual de row de audit log con click → detail modal
- `SettingsSection` — grupo de settings fields reutilizable (ej. OIDC section, Email defaults section, Alertas section)

## Metodología

Feature-first: Audit Log + Settings es la feature final que cierra la aplicación (observability + admin config). Reutiliza `PageShell`, `DataTable`, `EmptyState` de HT-28. Extrae `AuditLogEntry` y `SettingsSection` como componentes especializados. `SettingsSection` es especialmente importante para extensibilidad: nuevas settings can agregarse sin tocar la estructura general. Esta HT tambien completa los empty states en TODAS las pantallas previas (coordinación con HT-29 a HT-35).

## Criterios de Aceptación

- [ ] Audit Log con filtros y JSON diff funciona
- [ ] Settings solo visible para superadmin en scope global
- [ ] Settings CRUD funciona
- [ ] Empty states en todas las pantallas
- [ ] Loading skeletons en todas las vistas
- [ ] Diseño matchea frames de Pencil (via MCP)

## Definition of Done (DoD)

Cada feature se considera terminada SOLO cuando cumple estos 3 gates:

### Gate 1: Validación Visual (Pixel-Perfect)
1. Levantar la app en dev (`pnpm --dir web dev`)
2. Navegar a la pantalla implementada
3. Tomar screenshot via herramienta (o manualmente)
4. Leer el frame correspondiente del diseño via Pencil MCP
5. Comparar screenshot vs diseño de Pencil lado a lado
6. Verificar:
   - [ ] Layout y espaciado coinciden
   - [ ] Colores y tipografía correctos
   - [ ] Componentes del Design System usados (no custom)
   - [ ] Responsive: verificar en 1440px, 1024px, 768px
   - [ ] Empty states coinciden con diseño
   - [ ] Dark/light mode si aplica
7. Si hay drift visual → corregir en código, NO en Pencil

### Gate 2: Integración con Backend
1. Conectar contra backend real (docker-compose up)
2. Verificar cada endpoint que la feature consume:
   - [ ] GET lista carga datos reales
   - [ ] POST/PUT crea/edita correctamente
   - [ ] DELETE (soft) funciona con confirmación
   - [ ] Errores del backend se muestran correctamente (toast + mensaje)
   - [ ] Loading states mientras espera respuesta
   - [ ] Paginación cursor-based funciona
   - [ ] Filtros y búsqueda funcionan
3. Verificar auth:
   - [ ] Sin token → redirect a login
   - [ ] Token expirado → refresh o redirect
   - [ ] Rol insuficiente → mensaje de error, no crash

### Gate 3: Funcionalidad Completa
1. Todos los criterios de aceptación de la HT cumplidos
2. Componentes reutilizados del Design System (no duplicados)
3. Nuevos componentes extraídos a `components/shared/` si aplican
4. Zero errores en console del browser
5. Zero warnings de TypeScript
6. `pnpm --dir web lint` pasa
7. `pnpm --dir web typecheck` pasa sin errores
