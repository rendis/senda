# HT-34: CRUD Views — Injectors + Adapters + Domains

## Objetivo
Implementar las vistas CRUD para Injectors (con herencia visual campo por campo), Adapters (con formulario dinámico por tipo), y Domains (con DNS records y verificación).

## Entregables

1. **Injectors**
   - Leer via Pencil MCP el frame "Screen/Injectors" (Layer 13)
   - Lista de definiciones con scope e indicador de herencia
   - Editor campo por campo con cadena de herencia visual:
     - Global: valor (readonly)
     - _system: valor o "hereda global" (readonly)
     - Workspace: input editable + [Guardar] + [🗑️ borrar override]
     - "Valor efectivo" muestra qué nivel provee el valor actual
   - Input type cambia según field_type: text, img (URL + preview), html, url, number, bool (toggle)
   - Fetch: `GET /api/v1/manage/t/{tc}/w/{wc}/injectors`

2. **Adapters**
   - Leer via Pencil MCP el frame "Screen/Adapters" (Layer 14)
   - Lista: nombre, tipo (badge SES/Gmail), scope, default (✓), rate limit, status
   - Crear/Editar: form dinámico según tipo:
     - SES: region, access key ID, secret access key
     - Gmail: OAuth client ID, client secret, refresh token, delegate email
   - Credentials: mostrar "••••••••" después de guardar (no retrievable)
   - [Test Connection]: envía email de prueba
   - Marcar como default: toggle
   - Fetch: `GET /api/v1/manage/t/{tc}/w/{wc}/adapters`

3. **Domains**
   - Leer via Pencil MCP el frame "Screen/Domains" (Layer 15)
   - Lista: dominio, status badge (Pending/Verified/Error), scope, última verificación
   - Detalle: status grande, tabla DNS records (copy button por fila), error message, [Verificar Ahora]
   - Timeline de verificaciones (últimas 5)
   - Registrar dominio: input + genera DNS records automáticamente
   - Fetch: `GET /api/v1/manage/t/{tc}/w/{wc}/domains`

## Reutilización

**Componentes que reutiliza de HT-28:**
- `PageShell` — layout principal
- `DataTable` — tablas de injectors, adapters, domains
- `FormDialog` — forms para crear/editar recursos
- `EmptyState` — cuando no hay recursos configurados
- `ConfirmDialog` — para acciones destructivas (delete adapter, delete domain, etc.)
- `ScopeIndicator` — mostrado en herencia de injectors, scope de adapters/domains

**Componentes nuevos a extraer:**
- `ResolutionChainViewer` — visualización de cadena de herencia (Global → _system → Workspace) para injectors campo por campo
- `JsonSchemaForm` — form dinámico generado desde JSON schema (para adapters con tipo SES/Gmail)

## Metodología

Feature-first: CRUD Views es un conjunto de 3 features (Injectors, Adapters, Domains) que comparten estructura. Reutiliza `PageShell`, `DataTable`, `FormDialog`, `EmptyState`, `ConfirmDialog` intensivamente. `ResolutionChainViewer` y `JsonSchemaForm` son extracciones clave: la primera visualiza herencia compleja, la segunda genera forms dinámicos. Ambas son reutilizables y extensibles para futuras features con herencia o configuración dinámica.

## Criterios de Aceptación

- [ ] Injectors con herencia visual campo por campo
- [ ] Override y delete override funcionan
- [ ] Adapters con form dinámico por tipo (SES/Gmail)
- [ ] Credentials ocultas post-guardado
- [ ] Test connection funciona
- [ ] Domains con DNS records copiables
- [ ] Verificar dominio funciona
- [ ] Diseño matchea frames de Pencil (via MCP)

## Definition of Done (DoD)

Cada feature se considera terminada SOLO cuando cumple estos 3 gates:

### Gate 1: Validación Visual (Pixel-Perfect)
1. Levantar la app en dev (`npm run dev`)
2. Navegar a la pantalla implementada
3. Tomar screenshot via herramienta (o manualmente)
4. Leer el frame correspondiente del diseño via Pencil MCP
5. Comparar screenshot vs diseño de Pencil lado a lado
6. Verificar:
   - [ ] Layout y espaciado coinciden
   - [ ] Colores y tipografía correctos
   - [ ] Componentes del Design System usados (no custom)
   - [ ] Responsive: verificar en 1440px, 1024px, 768px
   - [ ] Empty states coinciden con diseño
   - [ ] Dark/light mode si aplica
7. Si hay drift visual → corregir en código, NO en Pencil

### Gate 2: Integración con Backend
1. Conectar contra backend real (docker-compose up)
2. Verificar cada endpoint que la feature consume:
   - [ ] GET lista carga datos reales
   - [ ] POST/PUT crea/edita correctamente
   - [ ] DELETE (soft) funciona con confirmación
   - [ ] Errores del backend se muestran correctamente (toast + mensaje)
   - [ ] Loading states mientras espera respuesta
   - [ ] Paginación cursor-based funciona
   - [ ] Filtros y búsqueda funcionan
3. Verificar auth:
   - [ ] Sin token → redirect a login
   - [ ] Token expirado → refresh o redirect
   - [ ] Rol insuficiente → mensaje de error, no crash

### Gate 3: Funcionalidad Completa
1. Todos los criterios de aceptación de la HT cumplidos
2. Componentes reutilizados del Design System (no duplicados)
3. Nuevos componentes extraídos a `components/shared/` si aplican
4. Zero errores en console del browser
5. Zero warnings de TypeScript
6. `npm run lint` pasa
7. `npm run build` compila sin errores
