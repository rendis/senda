# HT-32: Emails — Lista + Detalle

## Objetivo
Implementar la vista de lista de emails con filtros, búsqueda, paginación cursor-based, y la vista de detalle con timeline de eventos.

## Entregables

1. **Emails Lista**
   - Leer via Pencil MCP el frame "Screen/Emails List" (Layer 3)
   - Tabla con TanStack Table: destinatario, template type, status (badge), fecha, tracking ID
   - Filtros: status (multiselect), fecha (date range), template type (dropdown), búsqueda (text)
   - Paginación cursor-based: botones "Anterior" / "Siguiente" (no page numbers)
   - Export button
   - Fetch: `GET /api/v1/manage/t/{tc}/w/{wc}/emails`

2. **Email Detalle**
   - Leer via Pencil MCP el frame "Screen/Email Detail" (Layer 10)
   - Header: status badge grande + destinatario + subject
   - Info section: to, from, template, adapter, tracking ID (copiable), external ID, locale, fecha
   - Timeline vertical de eventos (sent, delivered, bounced, etc.) con timestamps
   - Snapshots collapsible: variables enviadas (JSON formateado), injectors resueltos
   - Error section (si bounced/failed): mensaje, bounce type, retry count
   - Fetch: `GET /api/v1/manage/t/{tc}/w/{wc}/emails/{trackingId}`

3. **Búsqueda avanzada**
   - Buscar por tracking_id, external_id, destinatario, remitente
   - Debounce en input (300ms)

## Reutilización

**Componentes que reutiliza de HT-28:**
- `PageShell` — layout principal
- `DataTable` — tabla de lista de emails con sort, filtros, cursor pagination
- `EmptyState` — cuando no hay emails en el período seleccionado
- `StatusBadge` — badges de estado (sent, delivered, bounced, failed, etc.)

**Componentes nuevos a extraer:**
- `EmailStatusTimeline` — timeline vertical de eventos de un email con timestamps
- `EmailDetailPanel` — panel derecho con metadata, snapshots, error info

## Metodología

Feature-first: Emails es una feature vertical completa (lista + detalle). Reutiliza `DataTable` de HT-28 para la lista y `StatusBadge` para estados. Extrae `EmailStatusTimeline` y `EmailDetailPanel` como componentes especializados que refuerzan la composición y podrían extenderse (ej. webhooks detail, audit log detail) con timeline similar.

## Criterios de Aceptación

- [ ] Lista de emails con filtros funciona
- [ ] Paginación cursor-based funciona (sin page numbers)
- [ ] Detalle muestra timeline de eventos
- [ ] Tracking ID y External ID son copiables (click to copy)
- [ ] JSON snapshots formateados y collapsibles
- [ ] Diseño matchea frames de Pencil (via MCP)
- [ ] Mobile: tabla colapsa a cards

## Definition of Done (DoD)

Cada feature se considera terminada SOLO cuando cumple estos 3 gates:

### Gate 1: Validación Visual (Pixel-Perfect)
1. Levantar la app en dev (`npm run dev`)
2. Navegar a la pantalla implementada
3. Tomar screenshot via herramienta (o manualmente)
4. Leer el frame correspondiente del diseño via Pencil MCP
5. Comparar screenshot vs diseño de Pencil lado a lado
6. Verificar:
   - [ ] Layout y espaciado coinciden
   - [ ] Colores y tipografía correctos
   - [ ] Componentes del Design System usados (no custom)
   - [ ] Responsive: verificar en 1440px, 1024px, 768px
   - [ ] Empty states coinciden con diseño
   - [ ] Dark/light mode si aplica
7. Si hay drift visual → corregir en código, NO en Pencil

### Gate 2: Integración con Backend
1. Conectar contra backend real (docker-compose up)
2. Verificar cada endpoint que la feature consume:
   - [ ] GET lista carga datos reales
   - [ ] POST/PUT crea/edita correctamente
   - [ ] DELETE (soft) funciona con confirmación
   - [ ] Errores del backend se muestran correctamente (toast + mensaje)
   - [ ] Loading states mientras espera respuesta
   - [ ] Paginación cursor-based funciona
   - [ ] Filtros y búsqueda funcionan
3. Verificar auth:
   - [ ] Sin token → redirect a login
   - [ ] Token expirado → refresh o redirect
   - [ ] Rol insuficiente → mensaje de error, no crash

### Gate 3: Funcionalidad Completa
1. Todos los criterios de aceptación de la HT cumplidos
2. Componentes reutilizados del Design System (no duplicados)
3. Nuevos componentes extraídos a `components/shared/` si aplican
4. Zero errores en console del browser
5. Zero warnings de TypeScript
6. `npm run lint` pasa
7. `npm run build` compila sin errores
