# HT-33: Templates — Types + Lista + Editor MJML

## Objetivo
Implementar el flujo completo de templates: lista de template types, lista de templates/versiones por tipo, y el editor MJML con preview dual panel.

## Entregables

1. **Template Types Lista**
   - Leer via Pencil MCP el frame "Screen/Template Types" (Layer 11)
   - Tabla: slug, nombre, adapter asignado (badge o "⚠️ Sin adapter"), scope, templates count
   - Indicador de herencia (🌐 global, ⚙️ _system, 📦 workspace)
   - Acciones: editar, asignar adapter
   - Fetch: `GET /api/v1/manage/t/{tc}/w/{wc}/template-types`

2. **Templates Lista + Versiones**
   - Leer via Pencil MCP el frame "Screen/Templates List" (Layer 12)
   - Lista por tipo: muestra si template es propio, heredado, o no existe
   - Badge "Heredado de [scope]" con opción de crear override
   - Tabla de versiones: version #, status (draft/published/archived), creado por, fecha
   - Solo 1 published (highlighted)
   - Acciones: editar (draft), publicar (draft + admin), archivar, preview

3. **Editor de Template (MJML)**
   - Leer via Pencil MCP el frame "Screen/Template Editor" (Layer 4)
   - Layout dual panel: editor izquierda, preview derecha
   - Editor con Monaco Editor: syntax highlighting MJML, autocompletado de variables
   - Tabs: Código / Visual (visual = placeholder para Fase 3 drag-and-drop)
   - Preview: toggle desktop/mobile, actualización en tiempo real
   - Metadata panel: subject, preview text, from_name, from_email, reply_to (React Hook Form + Zod)
   - Variables disponibles: sidebar con click-to-insert (inyectores + evento)
   - Locales: tabs por idioma, base = default_locale
   - Acciones: [Guardar Draft] [Preview] [Enviar Test] [Publicar ▼]
   - "Publicar" solo visible para admin+, requiere confirmación modal

4. **Test Send**
   - Modal: email destinatario + variables de prueba (JSON editor)
   - POST `/api/v1/manage/t/{tc}/w/{wc}/templates/{slug}/test`

## Reutilización

**Componentes que reutiliza de HT-28:**
- `PageShell` — layout principal
- `DataTable` — tablas de template types y versiones
- `EmptyState` — cuando no hay templates o types
- `FormDialog` — form para editar metadata, crear nuevo tipo, publicar
- `StatusBadge` — badges de versión (draft, published, archived)

**Componentes nuevos a extraer:**
- `MjmlEditor` — editor con Monaco, syntax highlighting MJML, autocompletado variables (base para fase 3 visual editor)
- `TemplatePreview` — preview dual panel (desktop/mobile toggle)
- `TemplateTypeSelector` — selector de tipo con badge de adapter

## Metodología

Feature-first: Templates es la feature más compleja (list, editor, versioning, locales). Reutiliza `PageShell`, `DataTable`, `EmptyState`, `FormDialog`, `StatusBadge` de HT-28 extensivamente. Extrae `MjmlEditor` (Monaco-based), `TemplatePreview`, y `TemplateTypeSelector` como componentes especializados. El `MjmlEditor` es extensible para la Fase 3 (visual builder) sin cambiar la interfaz pública.

## Definition of Done (DoD)

Cada feature se considera terminada SOLO cuando cumple estos 3 gates:

### Gate 1: Validación Visual (Pixel-Perfect)
1. Levantar la app en dev (`pnpm --dir web dev`)
2. Navegar a la pantalla implementada
3. Tomar screenshot via herramienta (o manualmente)
4. Leer el frame correspondiente del diseño via Pencil MCP
5. Comparar screenshot vs diseño de Pencil lado a lado
6. Verificar:
   - [ ] Layout y espaciado coinciden
   - [ ] Colores y tipografía correctos
   - [ ] Componentes del Design System usados (no custom)
   - [ ] Responsive: verificar en 1440px, 1024px, 768px
   - [ ] Empty states coinciden con diseño
   - [ ] Dark/light mode si aplica
7. Si hay drift visual → corregir en código, NO en Pencil

### Gate 2: Integración con Backend
1. Conectar contra backend real (docker-compose up)
2. Verificar cada endpoint que la feature consume:
   - [ ] GET lista carga datos reales
   - [ ] POST/PUT crea/edita correctamente
   - [ ] DELETE (soft) funciona con confirmación
   - [ ] Errores del backend se muestran correctamente (toast + mensaje)
   - [ ] Loading states mientras espera respuesta
   - [ ] Paginación cursor-based funciona
   - [ ] Filtros y búsqueda funcionan
3. Verificar auth:
   - [ ] Sin token → redirect a login
   - [ ] Token expirado → refresh o redirect
   - [ ] Rol insuficiente → mensaje de error, no crash

### Gate 3: Funcionalidad Completa
1. Todos los criterios de aceptación de la HT cumplidos
2. Componentes reutilizados del Design System (no duplicados)
3. Nuevos componentes extraídos a `components/shared/` si aplican
4. Zero errores en console del browser
5. Zero warnings de TypeScript
6. `pnpm --dir web lint` pasa
7. `pnpm --dir web typecheck` pasa sin errores
